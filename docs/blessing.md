# 祝福闪光说明

[返回首页](../README.md)

## 先整理，再追全

首次使用五星全收集前，请清除库存筛选，完整运行一次 **祝福闪光整理**。任务自动选择“获得时间：从新到旧”，记录头部、手部、脚部的顺序，按款式、部位、颜色保护满级收藏；三星满级为 5 级，四星和五星为 10 级。整理任务不升级。

默认保留已有锁定，只补锁缺少的颜色。开启“解锁不符合要求的祝福闪光”后，同时解锁未满级及多余重复项。获得时间排序下，已有锁定可能排在未锁叠放项后面，解锁也可能合并到前面，因此先完整记录已有状态，再局部定位处理；发生修改的部位最后再核对一次顺序。普通仓库遍历同时读取数量：锁定项每格一件，未锁定项先判断堆叠标记，再遮罩、放大数字区域进行 OCR。三个部位的实际数量（含实测月桂兔）与容量一致后直接保存 JSON，不再进入分解页面。标记或数量无法确认时保留失败截图，不猜成一件。

只有完整整理并通过数量核对后，才发布可供全收集使用的顺序基准。整理中断会使旧基准失效；旧版一键锁定 JSON、单独的数量扫描不能代替这次整理。换号或手动升级、解锁、分解后，请重新整理。手动获得新胚子可以作为新增区域处理。

月桂兔是活动特殊闪光，不可解锁或分解，不计入追全目标。暂按只有这一套特殊闪光处理，账号可以持有或未持有，无须填写数量。普通页实际观察优先；只有分解页记录时，完整扫描与容量相差 0 或 3 才允许自动核对，其他差值保留为不完整。

## 三种使用方式

| 入口 | 行为 |
| --- | --- |
| 幻境挑战 → 普通祝福闪光 | 按指定副本刷胚子，不升级 |
| 仅升级整理五星祝福闪光 | 读取整理基准，只处理库存，不花体力 |
| 幻境挑战 → 五星祝福闪光全收集 | 读取基准选缺色副本，刷取后分解四星及以下素材，再升级五星 |

全收集在进入幻境前校验基准；无有效基准时停止，不自动扫描补建。尚未收齐时仍遵循优先周本选项，再按 JSON 中各副本缺少的五星满级颜色总数降序选择，同分按图鉴顺序。列表找不到的副本本次跳过；快速挑战入口不可用、仍在关卡页且核对未消耗体力时，也继续下一顺位。找到可用副本后用剩余体力快速挑战一批，提交后不再换本，下次重新排序并检查可用性。所有候选都不可用时只处理已有胚子。即使上次缺噗灵，本次仍先刷胚子；没有体力也可以处理已有胚子。已全部收齐时不消耗体力，提示选择其他幻境。

升级顺序为：**上次未升完的对象 → 旧队列 → 本批新胚子**。同一部位的新批次从较早获得的开始处理；游戏未提供跨部位的精确时间，跨部位采用固定顺序。同款叠放无法区分每个副本的真实获得时间，合并后的胚子沿用已有队列优先级。

全收集确认本轮刷取成功后，进入分解页选择 **四星及以下素材**，一键放入、每批最多 100 件，直到自动放入数量为零。逐批核对容量减少量及闪光粒子增加量，只读右侧数字，不遍历分解列表；已有锁定收藏保留。分解结果未确认时停止，不重复提交。JSON 保存待清理标记；有有效基准且仍待清理时，下次全收集即使没有体力也会继续。没有刷取且无待清理记录，或“仅升级”任务，不触发这一步。

只升级缺色款式的未锁定五星，三星、四星不升级，也不追全颜色。升级使用 **五星及以下未锁定素材**，由游戏一键放入，包括其他五星胚子和重复项。已有锁定始终保留。升级后按 F 返回升级页；未满级继续放入、升级；确认十级、等级已满及颜色后，按 Esc 返回列表直接锁定新颜色，重复颜色保留未锁定。

缺噗灵或材料时保存当前对象并正常退出。不会自动素材激化；日志提示用户取消全收集模式刷噗灵，或自行通过其他方式获取。材料不足不等于其他胚子全部消失，剩余队列保留到实际核对后再更新。

## 如何避免反复全仓查找

- 基准保存完整观察顺序、处理优先级、位置提示和唯一满级锁定参照。位置提示不作为点击依据。
- 每轮只读取顶部新增区域，遇到最多三个按原顺序排列的唯一锁定参照后接上旧记录。同款旧胚子合并到前面时保留旧优先级。
- 每次升级返回先检查当前可见区域；找不到时滚动到记录位置附近，最多查找六页，逐页批量识别图标和等级，只核对可能的对象与边界参照。操作前仍重新确认名称、等级、选中高亮及锁按钮。
- 升级前只读取当前目标的叠放数量：单个胚子升级后直接完成该队列项，多件叠放保留剩余队列。新升级、锁定项的收藏立即保存，实际顺序由后续获得时间扫描确认后再用作定位参照。
- 只有两侧参照之间的范围（或列表端点）已完整检查，才能判断旧队列项不存在；不会根据旧坐标或材料不足猜测胚子消耗。未升完的对象丢失、参照变化或超过定位范围时停止并提示重新整理，不自动反复全仓搜索。
- 没有唯一锁定参照的部位，在本轮开始时完整读取一次；有参照的新增前缀最多读取 24 页。结束时直接保存收藏和队列，不再扫描分解页或统计未锁定材料数量。

首次整理会完整读取普通仓库并同时核对数量；全收集和仅升级任务按已确认锁定的满级颜色计算进度，结束后保留完整数量待核对状态，不影响下次全收集。可能已消耗的队列项在后续局部定位确认不存在时移除。大量手动改动或一次消耗导致位置偏移过大时，局部定位可能要求重新整理。

局部定位出现格子读取空缺时，保留基准及待处理项，下次运行继续核对。旧版因该错误作废的基准，会核对同轮本地日志、快照及全部操作确认状态，再恢复收藏与队列；恢复时重新观察旧版升级项的定位参照。

## JSON 保存什么

统一格式为 `schema_version: 1`，文件位于 `config/blessing/`。`inventory.json` 保留最近一次完整数量记录，`last_scan.json` 保存最新尝试，包括中断和数量待核对状态。后续任务读取最新状态，不绕过较新的失败记录使用旧基准。日志目录也保存同格式快照及操作证据。

| 字段 | 内容 |
| --- | --- |
| `items` | 名称、部位、星级、颜色、等级、经验、实际数量和识别标记；未知颜色为 `null` |
| `locks` | 已核实的锁定数量；追全过程仅确认收藏至少一件，不声称其他锁定数量完整 |
| `excluded_items` | 实际观察到的月桂兔，独立于追全目标 |
| `scan`、`unresolved` | 遍历、容量及数量完整性，识别失败内容；数量待核对不代表仓库为空 |
| `organization` | 完整整理标志、获得时间排序、三个部位的顺序记录、唯一条目编号、锁定状态、位置提示、队列优先级、未完成对象编号及未确认操作 |
| `pursuit` | 已保护颜色、缺色及对应副本，最近一次升级、资源不足原因和当前处理结果；`changes` 保存本轮开始／当前数量、目标总数、尚缺数量及新增／减少的颜色明细 |
| `record`、`created`、`catalog_version` | 写入来源、更新时间、证据目录和图鉴版本 |

`organization.slots` 是定位和队列记录，整理时的 `count` 与 `count_evidence` 保存每格实测数量和依据。升级期间这些观察值可能过时，不能用格子数或旧观察值计算当前容量；实际数量以 `items` 和 `scan.quantity_state` 为准。升级、锁定及刷本提交前写入待确认记录，确认后更新进度；不确定的库存修改禁止继续自动喂入。正常刷胚子及只读数量扫描保留已有整理基准，但不会凭空生成基准或新增物品数量。

`logs/blessing-lock/<时间>/locking.json` 保存整理操作；`logs/blessing-pursuit/<时间>/pursuit.json` 保存刷取及升级过程。软件端显示处理阶段、刷取与分解结果、新增颜色及最终进度；扫描期间每约 30 秒显示一次进度。逐格读取、局部定位、副本顺位和文件路径写入详细消息日志。
