# 使用与任务说明

[返回首页](../README.md) · [祝福闪光说明](blessing.md)

## 使用

从 [Releases](https://github.com/architect9331/MaaNikki/releases) 下载 Windows x64 运行包，完整解压后启动 `MaaNikki.exe`。源码压缩包不含运行环境。

客户端启动时会从 GitHub 检查最新已公开的正式版或预发布版，发现更新后后台下载对应 Windows x64 运行包，下载完成后在没有任务运行时提示安装。也可在设置中的更新区域手动检查并配置网络代理。尚未接入 Mirror酱，不需要填写 CDK。旧版客户端需要手动下载并安装一次带此功能的新版本，之后才能自动检查更新。

1. 核对按键设置，选择任务及选项。游戏未启动时可配置官方启动器 `launcher.exe` 路径，也可留空自动查找；启动游戏会固定先于其他任务执行。
2. 使用 16:9 游戏窗口，推荐 1920×1080；自动路线使用前台输入，运行时保持游戏在前台。切出游戏时需要前台操作的流程会暂停，切回后继续。
3. 提前解锁所需地图、传送点、能力和幻境关卡。捕虫、钓鱼、家园钓星等任务可指定允许使用的能力方案；轮盘已有所需能力时优先沿用。
4. 日常建议使用“全套日常”预设，朝夕心愿排在幻境挑战之前，跑图收集星光结晶排在星海拾光之前。启动游戏与巅峰赛默认勾选，周期任务已完成时保留勾选并自动跳过。使用定时执行时需保持 MaaNikki 运行，并满足相同的游戏窗口条件。

若提示游戏截图尺寸不符，请在游戏设置中选择 16:9 分辨率（如 1920×1080），确认实际窗口仍为 16:9，再重新运行。窗口最大化后可能跟随屏幕可用区域改变比例，应以实际游戏画面为准；所有任务的框架截图统一为 1280×720，尺寸不符时会停止本批任务并显示实际尺寸。

常见任务失败会在恢复页面前保存现场到 `debug/on_error`，包含截图与同名 JSON；识别和操作摘要也会写入 `debug/messages`。截图保留完整画面，只遮左下角 UID 的小区域。开启“帮助改进软件”时，失败现场沿用现有 Sentry 上报；关闭后仍保留本地记录。截图失败或超出上报限制时会记录状态，不保证每次都有远端附件。

默认提供三个页签，顺序为“全套日常”“开荒辅助”“祝福闪光全收集”。第三页包含“一键整理祝福闪光”和“幻境挑战”，后者默认使用五星祝福闪光全收集模式。已有配置首次升级会更新默认页签名称、顺序并补上全收集页，自定义页签保留；之后不会反复添加已删除的默认页签。

**开荒辅助**使用独立预设，持续运行到手动停止，不与日常任务同时运行。交互键为键盘按键时，拾取等辅助操作支持切出游戏后后台运行；鼠标交互只在前台执行，游戏最小化后暂停。自动钓鱼需先手动抛竿，切出游戏后暂停。对白辅助不选择分支，清洁辅助不自动靠近动物或开始清洁；清洁跳过图标与部分剧情动画共用，也可能跳过相应剧情动画。

**当前点钓鱼**需先站在钓点并面向水面，默认最多抛竿三次；鱼已钓光或位置不适合时结束。“钓鱼前打窝”需解锁万物交响能力。路线钓鱼会在鱼已钓光时继续后续钓点。

### 开发模式

在“设置 → 调试设置”中开启开发模式，可显示路线测试和日常子任务测试。

- 路线测试选择本地 JSON，支持内置路线（`resource/routes/daily/`）、工坊导出和自行编辑的路线。默认“路线导航”执行移动、跳跃、传送和等待，跳过采集、拍照等任务动作。缺少起始传送点时，先到第一个点位附近。
- “家园完整流程”支持本地家园路线，按点位执行钓星、下落攻击、传送和等待，消耗实际钓星次数。可通过“采星允许使用的能力方案”选择能力配置。
- “漂流瓶全点位”提供“路线 1 · 无界枢纽（原有 6 点）”和“路线 2 · 星梦群屿·海滩（4 个点）”，也可选择本地星海漂流瓶路线。每个点都尝试拾取，成功后继续走完全程；此模式单独执行所选路线。
- 朝夕与星海子任务可独立运行已适配流程，用于调试具体任务；幻境和互动项目会实际执行。

路线记录保存在 `logs/navigation/`：`route.json` 是启动时的原始路线快照，`execution.json` 是本次执行的点位和动作，`result.json` 保存执行模式、结果及跳过的动作。运行期间使用这份固定快照。

`events.jsonl` 保存实际尝试的定位方法、候选位置、分数和校验结果；失败现场、到点截图和停步记录用于核对偏移。本次整理移除了逐帧强制计算三种方法及逐帧截图的临时对比功能，定位恢复为按需计算，已有历史日志保留。

日常路线和路线测试共用导航及恢复入口。小地图连续定位失败时，会先停止移动，必要时打开大地图复核角色位置，再返回当前路线段。灰度匹配偏弱时尝试地形边缘匹配；仍未达标时，根据可信视角排除光锥区域，并检查分数、特征峰值、有效地形覆盖率及与灰度候选的位置一致性。位置或方向仍无法确认时停止并记录原因。

“灰度相似度”指小地图与参考地图的明暗纹理相似度，数值并非屏幕亮度。地形边缘候选达到可信分数时直接采用；未达标的候选只记入诊断，不否决后续光锥外匹配。不同方法的分数不能直接当成相同口径的定位准确率。

参考地图中的纯黑区域表示未采集地形。灰度、地形边缘、光锥外匹配、大地图定位和视角背景对齐共用缺图排除规则：按候选位置排除未采集区域及其边界，要求选中区域至少有 60% 的已采集地形。缺图产生的无效候选不参与定位峰值计算；视角识别同时屏蔽这些区域产生的假边缘。

漂流瓶路线 1 位于 `resource/routes/daily/xinghai_bottle.json`，保持原有 6 个拾取点与 1.0 到达半径。路线 2 位于 `resource/routes/daily/xinghai_bottle_2.json`，复用“星梦群屿·海滩”的已有传送落点，先经过最后补充截图的点位 P01，再依次经过此前三张截图的 P02–P04；坐标由地图中心匹配提取，拾取点半径同为 1.0，`params.source_entry` 记录对应工坊素材编号。

正式漂流瓶任务先跑路线 1，尚未完成拾取时继续路线 2，确认数量达到任务要求后立即结束。后续路线按首条路线的 `fallback_routes` 列表顺序追加，不递归展开其他路线的列表。导航中断后须返回可移动主界面才继续；手动停止或无法确认按键释放时终止。每条路线的已确认拾取数累计到下一条，查找过程另存 `bottle_route_result` 日志。

两种路线模式都会在漂流瓶点停稳复核；`events.jsonl` 中的 `bottle_arrival` 记录采样坐标、目标坐标、到达定位及 `point-*.png` 截图。“漂流瓶全点位”还会实际尝试拾取，`bottle_result` 记录交互提示和拾取结果，`result.json` 汇总计划点数、实际尝试点数和确认拾取次数；“路线导航”跳过拾取动作。路线走完表示完成本轮点位检查，拾取数量单独统计；中途停止时也保留已完成点位的结果。`forward_stop` 记录松键提交耗时与定时偏差，`arrival_check` 记录停止前后位置，供核对到点偏移；这些时间不代表游戏内部处理按键的时刻。


## 日志

软件端显示任务进度、结果和需要处理的问题。完整任务消息按天和进程保存在 `debug/messages/*.log`，采用每行一条 JSON 的格式：`timestamp` 为时间，`action` 为任务节点，`message` 为完整文本，`display` 为界面摘要（仅写文件时为 `null`）。软件的“导出日志”会一并打包这些记录。

### 自动错误上报

正式运行包默认开启“设置 → 通用 → 帮助改进软件”，可随时关闭。开启时向 MaaNikki 的 Sentry 项目发送崩溃、版本、硬件摘要、任务运行统计，以及失败任务的相关日志和错误截图。0.x 正式版同样支持上报；调试 / 开发构建默认关闭。

失败诊断只读取本次任务在 `debug/` 下的相关 `.log` 片段和新生成的 `on_error/` 截图；日志总量最多 1 MiB，单文件最多 512 KiB，截图压缩包最多 5 MiB。运行追踪按 10% 采样，任务失败事件及其诊断证据独立上报；服务配额和网络状况仍会影响接收。`logs/navigation/` 等路线记录仍需手动导出。

上报使用经过哈希的机器标识关联同一设备，关闭 SDK 的默认个人信息采集。日志正文和截图仍可能包含游戏账号信息，并未保证完全脱敏。接收地址由 `interface.json` 的 `telemetry.sentry` 配置，随运行包分发；该 DSN 是公开的事件接收地址，不是管理凭据。

运行包需要重新构建后生效。当前未配置原生调试符号上传，Rust 崩溃堆栈的源码行号可能不完整；任务失败节点、日志和截图可独立用于排查。

## 任务范围

- **朝夕心愿**先完成不耗体力的已适配项目，不足 500 分时再按当天要求执行幻境。累计消耗活跃能量作为进度条件，不单独增加挑战次数；同轮后续幻境清体力后，必要时只复核积分和领奖。小游戏、升级祝福闪光、制作服装尚未适配。
- **幻境挑战**所有消耗方式的目标关卡始终可见、可编辑，其他消耗方式的选项标注“补分备用”，供朝夕心愿按当天任务需要补分；剩余体力使用当前消耗方式对应的目标。悬停标记可查看使用条件。
- **跑图收集星光结晶**是独立的每日任务，不受星海拾光积分和子任务开关影响。匹配到路线后完整跑完，可靠检查全部视野均无标记时视为今日已收集。默认日常预设会在星海拾光前运行；旧配置首次升级时会将原跑图开关拆成独立任务并保留勾选状态。
- **星海拾光**只执行已适配项目。椰果采摘与拍照、星愿碎片投递与拍照、泡泡合影、海螺活动及跳上泡泡尚未适配。全部 15 个已适配子任务默认开启，可逐项关闭；制造泡泡默认按具备对应能力处理。聚会聊天仅向已识别的聚会频道发送一次设定消息。展开选项后固定显示 8 天轮换表和各组可达积分，无法凑满 500 分的行标黄并说明被关闭或未适配的项目；折叠时保留缺分警告摘要。“收集星光结晶”子任务仅在当天有对应任务且仍需补分时执行，与独立跑图任务共用收集逻辑。结晶定位需要摇铃显示标记，关闭单独的摇铃任务不影响结晶定位所需的摇铃。

星海拾光的子任务选项按实际调度的优先级、同级再按积分从高到低排列。同级同分的实际执行保留游戏任务卡片顺序，达到 500 分后停止补分。摇铃优先；其次是动物互动、拍照、摆饰、点赞、音乐和聊天；随后是星愿瓶合影、流星及星芒之翼合影，再是投递信笺和制造泡泡，然后按需收集结晶，漂流瓶最后尝试。
- **家园日常**按首个钓星点的结果自动选择双点路线或捷径。巨陨星只作提示，需要手动处理。
- **奇迹之旅**先检查旅行秘宝但暂不领取，领完旅行任务后再统一领秘宝；秘宝和任务均无奖励时不再返回秘宝页面。乐园构想单独勾选，只领取任务奖励；未勾选的项目不会领取。
- **邮箱领取**默认排在奇迹之旅奖励之后，从美鸭梨进入邮件并领取全部附件，确认奖励后返回主界面。领取全部按钮为灰色时按无附件处理。
- **商城任务**根据账号状态跳过当前周期已完成项目。礼包逐个确认，水晶兑换逐种确认，部分完成后下次只补剩余项目。未找到或已售罄的水晶商品按本月已兑换处理；兑换后仍有额度时不记为整月完成。
- **巅峰赛**需要提前解锁，成绩取决于衣柜和养成。赛事嘉奖与兑换默认关闭；开启兑换会消耗赛事货币。

## 本地账号状态

`config/account_state.json`（schema_version 2）统一保存周期任务和完整祝福闪光记录。首次写入时自动导入旧 `config/blessing/inventory.json` 与 `last_scan.json`，旧文件保留作备份，此后以账号状态文件为准。周期记录只由已确认的游戏结果更新，不根据计划中的操作标记完成。

周期按北京时间凌晨 4 点切换：礼包以周一为周起点，水晶以每月 1 日为起点，巅峰赛以每月 1 日、16 日为起点。任务列表显示“将运行”或“已完成”；已完成项目自动变灰，保留勾选，新周期自动恢复。

右上角“收集进度”按钮打开祝福闪光收集进度页，展示已确认满级并锁定的五星颜色，按副本、套组、部位排列，可搜索和筛选未收齐项目。数量待复核不会清空已确认收藏；有未确认操作时会提示重新整理。

当前记录与旧库存一样对应本机正在使用的一个游戏账号，不依据 MXU 配置标签区分账号，也不自动识别换号。换号后请先备份并移走 `config/account_state.json` 和旧 `config/blessing/`，再重新整理；手动改变周期任务状态后也需移除对应任务周期记录以重新检查。
